# AGENTS.md

A Quarto extension (`folium-typst` format) providing a Typst template for NBIS PDF reports: cover page with contributors grouped by role, logo, background image, Font Awesome icons.

## Commands

```bash
quarto render reports/demo.qmd     # exercises most markdown/Typst features
quarto render reports/report.qmd   # minimal example matching the README
```

`index.qmd` is the HTML homepage of the documentation site (`format: html`), not a PDF example.

No build system, linter, or test suite — verify changes by rendering both and inspecting the PDF. Set `keep-typ: true` in a report's `format.folium-typst` key to also emit the intermediate `.typ` file, useful for seeing what the filters/template partials actually produced before Typst compiles it.

## Architecture

`_extensions/folium/_extension.yml` registers the `typst` format's `template-partials` (`typst-template.typ`, `typst-show.typ`), `filters` entries (`folium.lua`, and `folium-callout.lua` at `post-ast`), and a default `font-paths` pointing at the extension's own bundled fonts. Any `.qmd` with `format: folium-typst` pulls all of this in automatically — **the extension is self-contained under `_extensions/folium/`** (fonts and the Font Awesome Typst package live there too, not at the repo root), so it works whether installed via `quarto add` or `quarto use template`.

The project is distributed two ways:

- **Extension** (`quarto add`): only `_extensions/` is installed.
- **Template** (`quarto use template`): `_extensions/`, `_quarto.yml`, `index.qmd` and everything in `reports/` (including the demos) are downloaded, so `.quartoignore` must not exclude them. `_quarto.yml` references the root `assets/` (site theme, favicon, images, `custom.lua`), so those are copied as well.

Rendering pipeline:

1. **`folium.lua`** runs first. It wraps inline Pandoc `Code` nodes in `#inline-code[...]`, wraps spans with a size class (`.largest`, `.larger`, `.large`, `.small`, `.smaller`, `.smallest`) in `#text(size: ...)[...]`, neutralizes any `Cite` AST nodes found in metadata back into literal `@id` text, recursively fills missing `folium` presentation values from the internal `folium-defaults` map, and drops `section-numbering` when `number-sections` is off (the extension supplies a default pattern, which alone would number headings regardless). Inline code must be wrapped at the AST boundary rather than with a global `show raw.where(block: false)` rule because Pandoc's `Skylighting` code blocks use non-block `raw` elements for individual tokens. The `inline-code` function in `typst-template.typ` paints the background with `highlight`, not `box`: a box cannot break across lines, so a long span would jump to the next line as a unit and leave a gap, and trailing punctuation would land beside its first line. `highlight` reserves no space, so the padding is an `h(3pt)` on each side plus an equal `extent`. A single token longer than a line (no spaces, `/` or `-`) still runs past the margin; adding zero-width break points was rejected because they would be copied along with the code. Quarto parses metadata as Markdown, so a standalone `@mention` would otherwise be read as a pandoc citation (an email such as `name@nbis.se` is not affected) and fail compilation when there's no bibliography. This only touches metadata; real citations in the document body are untouched.
2. **`typst-show.typ`** is the per-document entry point Pandoc generates into: it calls `#show: folium.with(...)`, translating standard YAML frontmatter (including `lang`, `region` and `section-numbering`), presentation values under `folium`, and report data under `nbis` into Typst function arguments. `folium` owns `class`, `background`, `logo`, `logo-height`, and `font-size`; `nbis` owns `id` and `contributors`. Setting `folium.logo` or `folium.background` to `false` leaves it out.
3. **`typst-template.typ`** defines the `folium(...)` function and styling: color palette, heading/table/callout/badge styles, block quotes (Pandoc emits `#quote(block: true)`, styled with a `show quote` rule), code block corners (Quarto's raw block rule is overridden with a `set block(radius: …)`, but Pandoc's `Skylighting` helper passes its own `radius: 2pt` explicitly, which a `set` rule cannot override, so `show block.where(radius: 2pt)` rebuilds that block), and the two-stage layout — `setup-cover-page` (background + logo) → `pagebreak()` → `setup-body-page` (numbered pages with an `id` header).

Quarto assembles the Typst document from its partials in this order: `numbering.typ`, `definitions.typ`, `typst-template.typ`, header includes, `page.typ`, `typst-show.typ`. Quarto injects `#import "@preview/fontawesome:0.5.0": *` into the header includes whenever a callout is rendered, which would shadow the vendored Font Awesome copy, so the vendored library is imported in `typst-show.typ` (after the header includes) rather than in `typst-template.typ`. Quarto's own `toc` and heading handling live in its default `typst-template.typ`, which this extension replaces: there is no automatic table of contents (reports add `#outline()` themselves), and heading numbering is applied by `folium(...)` from `sectionnumbering`.

Callout structure is constrained by Quarto: a callout with a cross-reference id (`nte-`, `tip-`, `wrn-`, `cau-`, `imp-`) is wrapped in a `figure`, and Quarto's show rule in `definitions.typ` rebuilds it by position (`old_callout.body.children.at(0)`, then `.body.body.children`, title at index 1, or index 0 when there is a single child). The `callout` function in `typst-template.typ` therefore keeps the icon and the title as the only two children of the title block, with no whitespace between them, and leaves the title as plain content, because Quarto's `empty()` helper treats a `styled` element (such as `text(weight: 700)[…]`) as an empty title and drops it. The bold title style is applied instead by `show block.where(radius: callout-title-marker)`, a marker radius of `0.01pt` that Quarto copies along when it rebuilds the block. Do not match on a default field value such as `sticky: false`: `where` also matches blocks that never set it, and every callout body turns bold. The type is recognised by the `icon_color` Quarto passes (`callout-types`). As in `styles.scss` of the documentation site, the note follows the brand color and its header is that color tinted 90% toward white, the other types keep the header colors Quarto passes, and the icon and title are in the body text color for every type; the type color only selects the header and the icon shape. Quarto's Typst writer does not pass the callout appearance to `callout`, so a simple callout would look like a default one. `folium-callout.lua` therefore runs at `post-ast`, where the `Callout` node has the resolved appearance (`minimal` is `simple` with no icon, and the `callout-appearance` document option is already applied), and replaces simple callouts with a call to `callout-simple`: the icon (in the text color) beside the body, no header and no default title, a bold title line only when the author gave one, and just the body for minimal. Callouts with an id and margin callouts are left to Quarto, because a cross-referenced callout needs the numbered title of the default layout and Quarto wraps it in the figure that references point to. The generic `.callout` has type `none`, which Quarto treats as simple. The icon is placed by `callout-icon-box`, which keeps it in a fixed-width slot so titles start at the same x whatever the icon's proportions, and shifts it so its center is the center of the text's cap height (a line is only as tall as the cap height, so an icon aligned to the baseline stands above the text's center); the cap height is measured, not assumed. Quarto emits a default title as `[\nNote\n]`, whose leading space would widen the gap after the icon, so `trim-title` drops spaces at either end of the title. The outer block carries the corner radius and `clip: true`, so the square corners of the inner blocks do not show; never put a radius on the title block, which is the marker. A referenceable callout whose title consists only of inline code still loses its title ("Tip 1" instead of "Tip 1: code"), because `empty()` finds no text in a box or highlight; this is Quarto's limitation and a title that mixes text and code is fine. Check any change to `callout` with a referenceable callout, with and without an icon (`icon=false`), and one without a title, and compare the icon and title alignment of a default callout with a custom title against one with the default title.

Key invariant: `nbis.contributors` is a list of objects with a required `name` and optional `email`, `affiliation`, and `roles`. `affiliation` and `roles` can each be a scalar or list. `folium(...)` groups contributors by role in first-seen order, defaults missing roles to `Contributor`, and computes a shared grid width from the largest role group.

Free-text fields (title, names, emails, etc.) don't need manual escaping in Typst — Pandoc already escapes them correctly for the target format when it substitutes `$var$`. Don't reintroduce a Typst-side `sanitize()`; it can't see raw strings by the time they reach `typst-template.typ` (they arrive as already-escaped Typst content), so it would be dead code.

`assets/` (background image, logo, site styling) is demo/site-only content — not required for the extension to function in a consuming project. Fonts and the vendored Font Awesome Typst package live under `_extensions/folium/` instead.

## Documentation conventions

In the demo reports, the two `content-visible` / `content-hidden` code samples use doubled braces on purpose, for example `::: {{.content-visible when-format="html"}}`, written as an escape so that Quarto does not process the sample. Do not change them without the maintainer's say-so. Note that with Quarto 1.10.18 the Typst output shows the doubled braces literally (single braces in the same fenced block are also displayed unprocessed), so the maintainer may want to revisit this.
